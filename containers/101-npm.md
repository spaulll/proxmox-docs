# CT 101, Nginx Proxy Manager

CT 101 is the reverse proxy and SSL manager for the lab. The container whose service almost everything else refers to: the `.myownserv.duckdns.org` names point to it, the `npm` tag is the only PVE tag that describes its role, and the proxy-host files under `/data/nginx/` show what it exposes without reading host-level docs.

## What runs inside

Active systemd services:

| Service | Unit file | Description |
|---|---|
| `npm.service` | `/usr/lib/systemd/system/npm.service` | Node admin process on 3000 |
| `openresty.service` | `/usr/lib/systemd/system/openresty.service` | Nginx/OpenResty web server |
| `ssh.service` | `/usr/lib/systemd/system/ssh.service` | SSH on 22 |
| `postfix.service` | local mail transport |
| `cron.service` | `/etc/init.d/cron` |
| `systemd-networkd.service` | container network |

The `npm` node process (`node index.js --abort_on_uncaught_exception --max_old_space_size=250`) runs with a 250 MB max. Writes to `/data/logs/`. `openresty` listens on 80, 81, 443. 81 is the admin UI (`production.conf`); 443 is SSL proxy for hosts.

Also runs `postfix` (25 localhost) and `cron`. Cron shows no errors, but no scheduled tasks in `/etc/cron.d` or `/etc/crontabs` (mostly empty). The `npm` service does its own SSL renewal: calls `/etc/letsencrypt/live/npm-2/` and logs renewals hourly (`SSL Renewing` at 14:25, 15:56, 16:56, 17:56, 18:56, 19:56). Certificate files are symlinks to `/data/letsencrypt/`.

Port 3000 is the NPM admin API; `production.conf` proxies `/api/` through it. 80 serves proxy-host rules; 81 serves the admin UI (`root /app/frontend`); 443 handles SSL and rejects default SSL handshake with 444 when host is `localhost`.

`fallback_access.log` / `fallback_error.log` under `/data/logs/` are empty at capture, rotated by logrotate. No `/etc/nginx/proxy_host/` inside; all proxy-host rules come from `/data/nginx/proxy_host/*.conf`.

## Network and ports

| Port | Process | Purpose |
|---|---|
| 80/tcp | `nginx` (openresty) | proxy hosts |
| 81/tcp | `nginx` | admin UI |
| 443/tcp | `nginx` | SSL proxy hosts |
| 3000/tcp | `node` (npm) | admin API |
| 22/tcp | `sshd` | SSH |

Admin UI listens on 81, not 443. 443 is only for proxy-host SSL; admin is protected by being on 81 and requiring login through `/api/`.

Container gets `net0` from `vmbr1`, same as CT 106 and lab guests. `/etc/resolv.conf` has `nameserver 10.10.10.1` and `nameserver 192.168.0.147`. DHCP, lease renews regularly, ~12 h lifetime (31603 s at capture).

`/etc/network/interfaces` isn't visible inside (managed by `systemd-networkd`). The host sets `nameserver` to `10.10.10.1`, so the proxy resolves through the lab router — consistent with OpenWrt's `dnsmasq` forwarding to AdGuard.

## SSL

NPM manages SSL through `npm.service`. `/etc/letsencrypt/live/npm-2/` has symlinks to the archive (`cert7.pem`, `fullchain7.pem`, `privkey7.pem`, `chain7.pem`). A custom cert is at `/data/custom_ssl/npm-3/` (`fullchain.pem`, `privkey.pem`). `proxy_host/1.conf` references `/etc/letsencrypt/live/npm-2/fullchain.pem`; `proxy_host/10.conf` references the custom path. `ssl-ciphers.conf` is standard.

`npm.service` log shows `Renewing SSL certs expiring within 30 days` hourly. Last renewal before capture: 19:56 on 2026-10-31, with `Completed SSL cert renew process` after. Cert (symlink `cert7.pem`) issued for `npm-2`; custom SSL (`npm-3`) separate.

Certs are inside the container filesystem (`/etc/letsencrypt/`, `/data/custom_ssl/`). Restoring from B2 restores these paths.

## Data

`/etc/nginx/` holds static nginx/openresty config. `/data/nginx/` holds dynamic rules: proxy hosts, redirection hosts, dead hosts, temp files, stream configs. `proxy_host/` has 14 `.conf`; `default_host/` and `redirection_host/` empty. `/data/custom_ssl/npm-3/` holds one custom cert, used by `asus.lan` only. `/data/logs/` holds access/error logs.

No bind mounts. Everything is in the 3.9 GB root filesystem. Weekly B2 backup includes the 4 GB root; archive for 2026-10-25 was 597 MB.

NPM admin state is in `/data/nginx/` and `/etc/letsencrypt/`. Rebuild from archive restores the config and certs, but the upstream proxy rules (hostnames, ports) should be verified after.

## Recovery

Backed up weekly. Restore brings back nginx/openresty config, NPM database, SSL certs, proxy-host rules. After restore:

- verify `npm.service` starts (`systemctl status npm openresty`)
- verify proxy-host rules load (`nginx -t` or `systemctl status openresty`)
- confirm admin web (`curl -k https://npm:81/`) and proxy hosts (`curl -k https://npm.myownserv.duckdns.org/`)
- review SSL renewal (`systemctl status npm` or `/etc/letsencrypt/live/npm-2/`)

Admin interface requires a login; credentials aren't in this repo. Proxy-host rules reference upstream ports but include no auth details.

No services or files changed. All from `pct config`, `cat`, `ss`, `netstat`, `ps`, `systemctl`, `df`, and read-only inspection of `/etc/nginx/` and `/data/nginx/`.
