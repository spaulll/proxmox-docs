# CT 103, aria2

The download box. aria2 does the actual downloading; AriaFlow — a Telegram bot — drives it and yt-dlp, then organizes finished downloads into the media library on `/mnt/nas`. The only "front door" is Telegram; nothing here listens on the LAN.

| | |

The veth is rate-limited to 7 MB/s, so a big fetch can't choke the lab uplink.

## What runs inside

| Service | What it does |
|---|---|
| `aria2.service` | aria2c download daemon (websocket RPC on loopback) |
| `downloadbot.service` | AriaFlow bot (`prox-download-bot`) |
| `tg-bot-api.service` | local Telegram Bot API server — lifts the 20 MB forward cap to 2 GB |
| `sshd`, `cron` | SSH, cron |

The bot talks to aria2 over RPC on loopback and shells out to `yt-dlp` (`/bin/yt-dlp`) for video pages. The local Bot API server is in use, so forwarding Telegram files up to 2 GB works.

## The bot

Repo: https://github.com/spaulll/AriaFlow — Go, Apache-2.0, a heavy remod of DownloadBot.

Send it a link, a magnet/torrent, a video-page URL, or forward a file. It downloads with live progress, then organizes everything into the media library on `/mnt/nas`: `movies`, `series`, `anime`, `music`, `documents`, `Books`, `YouTube`, with `downloads` as staging. Multi-user with admin approval; regular users see only their own tasks. After organizing, it can trigger a Jellyfin library refresh.

## App layout

Everything lives in `/opt/prox-download-bot`:

- `ariaflow` — the bot binary, with `ariaflow.prev-*` copies kept from past updates
- `config.json` — bot token, admin ID, Jellyfin API key, organize roots. Secrets stay here; nothing is copied to these docs
- `users.json`, `tasks.json` — approved users and task state
- `telegram-bot-api`, `run-tg-api.sh` — local Bot API server binary and its launcher

## Backup

CT 103 is in the B2 weekly job (~560 MB archive). Like every container, `vzdump` skips bind mounts, so the media library on `/mnt/nas` is **not** in the backup — it's treated as replaceable. The bot's config, users, and task state are in the archive.

## What happens if something fails

| Failure | Effect |
|---|---|
| `aria2.service` stops | Downloads stall; the bot stays up. |
| `downloadbot.service` stops | No new bot commands; active aria2 tasks continue. |
| `tg-bot-api.service` stops | Forwarded files fall back to Telegram's 20 MB cloud cap. |
| Container lost | Restore from the B2 archive; the library on `/mnt/data` survives untouched. |
